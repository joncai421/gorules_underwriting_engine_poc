# Headless Underwriting Engine PoC

A working monorepo Proof of Concept demonstrating the modernization of an insurance
underwriting system from a **legacy hardcoded Spring Boot (Java 17)** service to a
**headless GoRules engine (TypeScript + `@gorules/zen-engine`)**, with automated
migration/parity tooling, a pluggable **AI Copilot** for `UNCLEAN` (referral) cases,
and a React **Admin UI** embedding `@gorules/jdm-editor`.

> See [`docs/initial_requirements.md`](docs/initial_requirements.md) for the full PRD.

## What it proves

1. **Legacy baseline** — rigid `if-else` underwriting rules (`CLEAN` / `UNCLEAN` / `DECLINE`).
2. **Migration tooling** — `npm run migrate` scrapes the Java source and rebuilds a GoRules
   JDM decision table.
3. **Shadow-mode parity** — `npm run verify-parity` proves **100% behavioral equivalence**
   between the Java service and the GoRules engine across 10 canonical cases.
4. **Configurable rules + hot-reload** — a headless REST engine with rule versioning.
5. **1-click rule onboarding** — new business rules (Occupation Class 4, Senior Multi-Morbidity)
   injected through the UI/API with zero backend code changes, flipping a `CLEAN` case to `UNCLEAN`.
6. **Future-proof AI extension** — a deterministic/mock (or live LLM) copilot that turns the
   GoRules execution trace into an underwriting brief, only for `UNCLEAN` cases.

## Prerequisites

- **Node.js 18+** (tested on Node 24) and npm.
- **Java 17** on `PATH` (or `JAVA_HOME` set) — needed only to build/run the legacy service.
  No global Maven is required: the bundled **Maven Wrapper** downloads Maven on first run.
- Network access on first build for `npm install` and the Maven Wrapper.

## Quickstart

```bash
# 1) Install all workspace dependencies (from the repo root)
npm install

# 2) Build + run the legacy Java service on :8080
cd legacy-java-service && ./mvnw spring-boot:run       # (Windows: .\mvnw.cmd spring-boot:run)

# 3) In another terminal: run the headless GoRules TS engine on :3001
npm run engine

# 4) In another terminal: run the Admin UI on :5173 (proxies /api -> :3001)
npm run ui
```

Or run engine + UI together: `npm run dev`.

## Verification checklist (PRD section 6)

```bash
# Engine self-test: loads v1/v2 and evaluates all 10 cases (< 5ms/case), asserts expected outcomes
npm run selftest

# Regenerate v1 JDM from the legacy Java source (deterministic AST/regex migrator)
npm run migrate
#   ... or emit the LLM-assisted migration prompt + JSON schema instead of writing files:
npm run migrate:llm

# Shadow-mode parity: Java :8080  vs  GoRules TS :3001  (exit 1 on any diff)
#   Requires both services running.
npm run verify-parity
```

Expected: `Self-test PASSED`, and `PARITY PASSED: 100% behavioral equivalence (10/10)`.

## API surface (GoRules TS engine, :3001)

| Method | Path                     | Purpose |
|--------|--------------------------|---------|
| GET    | `/api/rules`             | List rule versions + active id |
| GET    | `/api/rules/:id`         | Raw JDM JSON (for the editor) |
| PUT    | `/api/rules/:id`         | Save JDM + hot-reload (`?activate=true`) |
| POST   | `/api/rules/:id/activate`| Switch active version |
| POST   | `/api/rules/onboard`     | Create a version by appending rule rows |
| POST   | `/api/underwrite`        | Evaluate (`?aiAssist=true\|false`, `?rule=<id>`) |

Legacy Java (`:8080`): `POST /api/legacy/underwrite`.

### Example

```bash
curl -s -X POST "http://localhost:3001/api/underwrite?aiAssist=true" \
  -H "content-type: application/json" \
  -d '{"applicantId":"APP-1004","age":45,"bmi":29.5,"smoker":true,"systolicBp":145,"sumAssured":1200000,"medicalConditions":["FATTY_LIVER","HYPERTENSION_STAGE_1"],"occupationClass":2}'
```

Returns `decision`, `basePremiumLoadingPct`, `triggeredRules`, `executionTimeMs`, the GoRules
`trace`, and (for `UNCLEAN` with `aiAssist=true`) an `aiCopilotBrief`.

## Demo walkthrough (Admin UI)

1. Pick a rule version and click a preset applicant in the **Live Simulator** drawer, then **Run Simulation**.
   The matched nodes/rows light up from the returned trace; `UNCLEAN` cases render an **AI Copilot Assessment Card**.
2. Click **Onboard New Rule (Occupation Class 4 & Smoker Surcharge)** to regenerate `v2-onboarded-rules`
   with two new referral rows, then re-run **CASE-09** to watch it flip `CLEAN -> UNCLEAN`
   with `RULE_HIGH_RISK_OCCUPATION`.
3. Edit a cell directly in the decision table (e.g. lower the BMI threshold) and click **Save & Hot-Deploy**.

## AI Copilot modes

- **Deterministic / mock (default):** no API key required; synthesizes a rule-grounded brief from the trace.
- **Live LLM:** set `OPENAI_API_KEY` (optionally `OPENAI_MODEL`) or `ANTHROPIC_API_KEY`
  (optionally `ANTHROPIC_MODEL`) in the environment; falls back to mock on any error.

## Notes on parity

To stay byte-for-byte behaviorally identical to the JDM (`collect` hit policy + aggregator),
the legacy service evaluates **all** rules without short-circuiting, de-duplicates by `ruleId`
(preserving table order), resolves severity `DECLINE > UNCLEAN > CLEAN`, and sums loadings
(0 when the final decision is `DECLINE`). The rule order in `HardcodedUnderwritingService.java`
is kept in sync with `shared/rules/v1-migrated-rules.json`, which `npm run migrate` regenerates.
